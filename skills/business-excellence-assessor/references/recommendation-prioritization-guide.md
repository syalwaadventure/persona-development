# Recommendation Prioritization Guide

Recommendations must trace to a scored/evidenced gap.

## 1. Required traceability

`Evidence → Finding → Gap → Impact → Recommendation → Owner validation → Completion evidence`

A recommendation without this chain is generic and should be removed.

## 2. Priority dimensions

| Dimension | Question |
|---|---|
| Gap severity | How far is current practice from rubric/target? |
| Business/organizational impact | What result, risk, customer, process, or strategy is affected? |
| Urgency | Is there a deadline, compliance, operational, or decision need? |
| Evidence strength | Is the gap confirmed or only suspected? |
| Feasibility | Can the change be implemented with available authority/resources? |
| Dependency | What must happen first? |
| Sustainability | Will the action change the system or only close one symptom? |

## 3. Default categories

### Quick Win

Confirmed gap, high clarity, low-to-moderate effort, limited dependency, visible
benefit within approximately 0–3 months.

### Medium-Term Improvement

Requires cross-function coordination, process/KPI changes, capability building,
or system adjustment; approximately 3–12 months.

### Long-Term Transformation

Requires operating-model, technology, culture, investment, or multi-unit change;
usually >12 months.

Time horizons are defaults, not commitments. If the organization has not
provided timeline or owner, use `REQUIRES OWNER VALIDATION`.

## 4. Recommendation quality check

Each recommendation must specify:

- linked finding/gap;
- intended outcome;
- action;
- function owner, or placeholder;
- dependency;
- completion evidence;
- success KPI or observable condition;
- risk if not implemented;
- confidence.
